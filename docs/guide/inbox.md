# 通知中心

通知中心负责汇总和展示 AI Code Review 的审查结果，提供三个互补的通知渠道，确保开发者能够以最适合自己的方式获取审查反馈。

## 概览

| 渠道 | 适用场景 | 特点 |
| --- | --- | --- |
| 系统弹窗 | 即时提醒 | 跨平台桌面通知，审查完成时立即弹出 |
| 终端 Inbox | 日常浏览 | 命令行内快速查看，适合开发者工作流 |
| HTML 仪表盘 | 完整查看 | 浏览器中查看详细报告，支持搜索和筛选 |

三个渠道共享同一份数据源，已读/未读状态实时同步。

## 系统弹窗

系统弹窗在审查完成后立即触发桌面通知，让你第一时间了解关键问题。

### 支持平台

- **Windows**：使用 BurntToast 模块生成原生 Toast 通知
- **macOS**：使用系统原生通知中心
- **Linux**：使用 libnotify / notify-send

### 自动降级

当系统弹窗不可用时（例如缺少通知权限或未安装依赖组件），通知中心会自动降级到终端输出，确保重要信息不会遗漏。

::: tip 配置建议
在 Windows 上使用系统弹窗前，请确保已安装 BurntToast PowerShell 模块：
```powershell
Install-Module -Name BurntToast -Scope CurrentUser
```
:::

## 终端 Inbox

终端 Inbox 提供命令行内的通知管理功能，无需离开终端即可查看和处理审查结果。

### 命令列表

#### 查看所有通知

```bash
ai-review inbox list
```

显示所有通知的摘要列表，包含 ID、标题、严重等级、时间和已读状态。

#### 仅查看未读通知

```bash
ai-review inbox --unread
```

过滤并仅显示尚未阅读的通知，帮助快速定位新产生的审查结果。

#### 查看通知详情

```bash
ai-review inbox show <id>
```

查看指定通知的完整内容，包含问题详情、涉及文件和修复建议。执行此命令后，该通知会**自动标记为已读**。

#### 全部标记已读

```bash
ai-review inbox mark-all-read
```

将所有通知一键标记为已读状态，适用于批量处理后清理通知列表。

::: warning 注意
`ai-review inbox show <id>` 命令在展示通知详情后会自动将其标记为已读。如果你需要稍后再处理，请仅使用 `list` 命令预览摘要信息。
:::

## HTML 仪表盘

HTML 仪表盘提供浏览器内的可视化审查报告，适合深入查看和分析审查结果。

### 生成并打开仪表盘

```bash
ai-review inbox dashboard
```

该命令会生成 HTML 报告文件并自动在默认浏览器中打开。

### 功能特性

- **时间排序**：审查结果按时间倒序排列，最新的排在最前面
- **颜色编码状态**：不同严重等级使用不同颜色标识（红色 ERROR、黄色 WARNING、蓝色 INFO）
- **可展开的问题详情**：点击问题标题可展开查看完整描述和上下文
- **Diff 风格代码建议**：修复建议以 diff 格式展示，清晰标注新增和删除的代码行
- **搜索与筛选**：支持按关键词搜索、按严重等级或规则 ID 筛选
- **深色主题**：默认使用深色主题，减少长时间查看时的视觉疲劳
- **未读标记圆点**：未阅读的通知带有醒目的圆点标记

### 自动打开

当配置项 `dashboard.auto_open` 设为 `true` 时，异步审查（async review）完成后会自动生成并打开 HTML 仪表盘，无需手动执行命令。

::: tip 推荐配置
对于异步审查场景，建议在配置文件中启用自动打开：

```yaml
dashboard:
  auto_open: true
```

这样在后台审查完成后，你可以立即在浏览器中查看完整结果。
:::
